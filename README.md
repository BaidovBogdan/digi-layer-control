# DiGi Layer Control

Тестовый интерфейс управления картографическими слоями. Показывает температуру, ветер и инсоляцию, состояние mock-запросов и предпросмотр того, как включённые слои могли бы выглядеть на карте.

Предпросмотр схематичный: реальные геоданные и картографический движок в задании не подключались.

## Запуск

Требования: Node.js 20+ и npm.

```bash
npm install
npm run dev
```

Локальные проверки:

```bash
npm run build
npm run lint
npm run format:check
```

Чтобы увидеть ошибку запроса и повторную загрузку, откройте `/?mockError=wind`. Первый запрос слоя «Ветер» завершится ошибкой, а повторный — успешно. Параметр `?mockError=1` включает этот сценарий для всех слоёв.

Каталог загружается отдельно от интерфейса. Чтобы проверить список на 100 слоях, откройте `/?mockLayerCount=100`; допустимое значение — от 0 до 1000. Для проверки пустого каталога используйте `/?mockLayerCount=0`. Параметр `/?mockCatalogError=1` вызывает ошибку первой загрузки каталога; повторная попытка завершится успешно.

## Возможности

- включение и выключение слоёв;
- настройка прозрачности от 0 до 100%;
- состояния `idle`, `loading`, `success`, `error`;
- повторная загрузка после ошибки;
- асинхронная загрузка каталога с проверкой обязательных полей и уникальности ID;
- состояния загрузки, ошибки и пустого каталога с возможностью повторить запрос;
- mock-запросы с отменой при выключении слоя;
- защита от устаревших ответов при быстрых переключениях и повторных запросах;
- поиск и виртуализированный список при каталоге больше 20 слоёв;
- ограниченный предпросмотр первых трёх включённых слоёв с числом остальных;
- адаптивный интерфейс, клавиатурное управление и сообщения состояния для вспомогательных технологий.

## Архитектура

```text
src/
├── components/
│   ├── GlobalStyles.ts
│   ├── LayerCard.tsx       # контролы и состояние отдельного слоя
│   ├── LayerList.tsx       # поиск и виртуализация большого списка
│   ├── LayerSummary.tsx    # сводные счётчики
│   └── MapPreview.tsx      # условное отображение включённых mock-слоёв
├── features/layers/
│   ├── api.ts              # mock API каталога и данных слоёв
│   ├── store.ts            # vedro store и обновление отдельного слоя
│   ├── types.ts            # типы и начальное состояние
│   ├── useLayerCatalogController.ts # загрузка, проверка и повтор запроса каталога
│   └── useLayerController.ts # действия со слоями, отмена и защита от гонок
├── pages/LayerControlPage.tsx
├── App.tsx
└── main.tsx
```

В тестовом проекте каталог асинхронно возвращает mock API; в реальном приложении этот вызов заменяется REST endpoint. Ответ проверяется до попадания в store: нужны непустые уникальные ID и названия, текстовые описания и единицы измерения, а цвет должен быть в формате `#RRGGBB`. При успешной загрузке состояние создаётся по ID каталога. Состояния существующих ID сохраняются при повторной установке каталога, новые получают начальные значения.

Состояние слоёв хранится в `vedro`. Карточка выбирает состояние своего слоя. В установленной версии `vedro` подписка уведомляется при изменении store, затем библиотека сравнивает выбранное значение и вызывает React-обновление только при его изменении. Для каталогов свыше 20 строк карточки виртуализируются через `@tanstack/react-virtual`: монтируются видимые элементы и небольшой запас, высота строк уточняется по фактическому содержимому, а ключом служит ID слоя. Поиск применяется до виртуализации. Во время клавиатурной навигации виртуализатор временно монтирует весь отфильтрованный список, чтобы Tab проходил по каждому контролу; при обычной прокрутке остаётся включена виртуализация. Сводка и предпросмотр читают общий store, а предпросмотр ограничивает число одновременно показанных элементов.

Запросы каталога и данных слоёв разделены. Каталог отменяется при размонтировании страницы; повторные запросы получают sequence ID, чтобы устаревший ответ не затёр актуальное состояние. При обновлении каталога контроллер отменяет запросы удалённых ID. Запросы данных инициализируются и отменяются в контроллере. На каждый слой ведётся sequence ID: при выключении или новом запросе sequence меняется, поэтому ответ старого запроса отбрасывается, даже если API не успел обработать `AbortSignal`. Обработчик сигнала снимается при завершении mock-запроса, а контроллер освобождается после результата.

## GIS-интеграция

Задание проверяет управление состоянием слоёв, а не подключение карты. В этой версии нет MapLibre, GeoJSON или реальных тайлов: каталог и значения слоёв — демонстрационные mock-данные, а предпросмотр намеренно помечен как условный. Backend-источник каталога здесь не подключён. В полноценном приложении конфигурацию и загруженные данные можно передавать отдельному адаптеру карты, не связывая картографический движок с UI-компонентами.
