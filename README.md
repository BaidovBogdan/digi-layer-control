# DiGi Layer Control

Тестовый интерфейс управления картографическими слоями. Показывает температуру, ветер и инсоляцию, состояние mock-запросов и предпросмотр того, как включённые слои могли бы выглядеть на карте.

Предпросмотр схематичный: реальные геоданные и картографический движок в задании не подключались.

## Запуск

Требования: Node.js 20+ и npm.

```bash
npm install
npm run dev
```

Локальные проверки:

```bash
npm run build
npm run lint
npm run format:check
```

Чтобы увидеть ошибку запроса и повторную загрузку, откройте `/?mockError=wind`. Первый запрос слоя «Ветер» завершится ошибкой, а повторный — успешно. Параметр `?mockError=1` включает этот сценарий для всех слоёв.

## Возможности

- включение и выключение слоёв;
- настройка прозрачности от 0 до 100%;
- состояния `idle`, `loading`, `success`, `error`;
- повторная загрузка после ошибки;
- mock-запросы с отменой при выключении слоя;
- защита от устаревших ответов при быстрых переключениях и повторных запросах;
- адаптивный интерфейс, клавиатурное управление и сообщения состояния для вспомогательных технологий.

## Архитектура

```text
src/
├── components/
│   ├── GlobalStyles.ts
│   ├── LayerCard.tsx       # контролы и состояние отдельного слоя
│   ├── LayerSummary.tsx    # сводные счётчики
│   └── MapPreview.tsx      # условное отображение включённых mock-слоёв
├── features/layers/
│   ├── api.ts              # mock API, задержки, отмена и ошибка для демо
│   ├── store.ts            # vedro store и обновление отдельного слоя
│   ├── types.ts            # типы, конфигурация и начальное состояние
│   └── useLayerController.ts # действия, отмена и защита от гонок
├── pages/LayerControlPage.tsx
├── App.tsx
└── main.tsx
```

Конфигурация тестовых слоёв задаётся в `LAYER_DEFINITIONS`. Начальное состояние строится по этому списку, а запросы хранятся в `Map` по ID, поэтому расширение статического каталога не требует отдельной ветки компонента или ручной записи в объект начального состояния. Тип ID — строковый; получение и инициализация динамического каталога с backend в задании не реализованы.

Состояние слоёв хранится в `vedro`. Карточка выбирает состояние своего слоя. В установленной версии `vedro` подписка уведомляется при изменении store, затем библиотека сравнивает выбранное значение и вызывает React-обновление только при его изменении. Это сокращает лишние рендеры интерфейса; при большом каталоге стоимость самих селекторов также следует учитывать.

Запросы инициализируются и отменяются в контроллере. На каждый слой ведётся sequence ID: при выключении или новом запросе sequence меняется, поэтому ответ старого запроса отбрасывается, даже если API не успел обработать `AbortSignal`. Обработчик сигнала снимается при завершении mock-запроса, а контроллер освобождается после результата.

Модель состояния и конфигурация не копируются для каждого слоя. При переходе к сотням элементов интерфейсу понадобится виртуализация списка; в этом небольшом тестовом задании она не добавлялась.

## GIS-интеграция

Задание проверяет управление состоянием слоёв, а не подключение карты. В этой версии нет MapLibre, GeoJSON или реальных тайлов: предпросмотр намеренно помечен как условный. В полноценном приложении конфигурацию и загруженные данные можно передавать отдельному адаптеру карты, не связывая картографический движок с UI-компонентами.
